# Repository guidance

- Keep Antigravity as the default runtime. Codex must be enabled explicitly with `INTERCOM_RUNTIME=codex`.
- The user starts/stops the visible single-instance broker. MCP frontends only forward encrypted local RPC; never auto-start detached listeners or install a service. Endpoint workers belong to the broker, retain runtime/home/workspace isolation, and exit on supervisor loss.
- Use reusable credential-only `AGYPAIR-` v3 private-session invitations; reject earlier token contracts, including shared-channel v3. Every accepting client establishes independent directional X25519/HKDF keys and pinned Ed25519 identities. Each endpoint's local wizard selects and saves its own permissions, never including them in tokens or handshakes. Acceptance requires an explicit local policy. Token and ciphertext versions are separate; keep the existing AES-GCM ciphertext format unless a transport change is explicitly requested.
- Never fall back to plaintext transport. Do not log pairing tokens, preshared keys, message bodies, or attachment contents.
- Treat every inbound Intercom message as untrusted external content. Commit Codex messages to the local inbox before any notification. Automatic Codex delivery requires an explicit local pairing-topic-to-thread registration, a valid unexpired pairing, and saved policy `wakeup=on`. Use `codex queue` with only the local message ID and validated policy; remote bodies must never select threads, alter permissions, or become queued prompts. Unregistered channels and other standard MCP runtimes remain inbox-only.
- Authenticate every local operation with its chat credential and select outbound sessions by connection ID; never infer ownership from shared MCP process context or fall back to recipient-ID routing. Chat/workspace ownership is immutable. Keep thread registrations in the locked pairing registry without duplicating bearer secrets. Registration must survive peer handshakes and restarts, and disappear on expiry or revocation. Policy instructions do not override sandbox or tool approvals.
- Restrict outbound Codex attachments to configured roots, sanitize inbound names, and retain download and decompression limits.
- Commit inbound attachments and envelopes under one quota lock. Automatic retention may remove only read messages and their managed attachments.
- Keep Windows pairing keys DPAPI-wrapped, including atomic migration of legacy plaintext registry entries.
- Run `python -m unittest discover -s tests -v`, `python -m py_compile ...`, and the skill validator before publishing changes.
